================================================================================
PROBLEM STATEMENT
================================================================================

Agent calls fetch_logs tool successfully, gets results back, but then responds
as if it didn't receive any logs. Appears to be a regression from recent changes.

================================================================================
ROOT CAUSE IDENTIFIED
================================================================================

The bug is a COMBINATION of TWO features interacting badly:

1. CONTEXT INJECTION FIX (commit 8692862)
   - Merges user context into system prompt BEFORE the tool execution loop
   - Creates one large system message instead of multiple system messages

2. RESULT CACHING FEATURE (commit 620defd)
   - Caches large tool results automatically
   - Returns summary with sample events instead of full results
   - Sets "pending cache guidance" to tell agent to fetch chunks

THE INTERACTION (The Bug):
- When tool returns >5000 tokens, it gets cached
- Cached result returns summary with only sample events
- "pending_cache_guidance" is set to remind agent to fetch chunks
- Next LLM call: context injection merges cache guidance into system prompt
- Agent receives:
  * Tool result: SUMMARY (with few sample events)
  * System prompt instruction: "Fetch chunks using fetch_cached_result_chunk"
- Agent gets confused and responds as if no real logs were found
- Never analyzes the actual data because cache guidance overrides result processing

================================================================================
RECOMMENDED FIX (BEST APPROACH)
================================================================================

OPTION 2-3: Separate Cache Guidance from System Prompt Context

Current broken flow:
  System Prompt
    + User context injection
    + Cache fetch guidance
  User Message
  Assistant Message (with tool_calls)
  Tool Result (cached summary)  ← Agent confused, doesn't analyze

Fixed flow:
  System Prompt (original only)
  User Message
  Assistant Message (with tool_calls)
  Tool Result (with actual events, even if cached)
  Cache Fetch Guidance (as separate system message, AFTER result)

Benefits:
- Agent sees tool result content first, before fetch instructions
- Clear separation of concerns
- Maintains caching benefits
- Tool results always visible

Implementation:
1. Don't merge cache guidance into system prompt context
2. Return full result to agent (not just summary)
3. Add cache guidance as separate message AFTER tool result processing
4. Agent naturally processes result first, THEN sees optional fetch instructions

================================================================================
SHORT TERM WORKAROUND
================================================================================

To immediately restore functionality without code changes:
1. Disable result caching: settings.enable_result_caching = False
   This bypasses the caching feature and ensures full results are visible

However, this increases context usage and defeats the caching benefit.
