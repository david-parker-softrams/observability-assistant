CHAT TEXT SELECTION INVESTIGATION - QUICK SUMMARY
================================================================================

PROBLEM:
--------
Users cannot select or copy text from chat messages in LogAI TUI.
Impact: Users cannot copy error messages, logs, or agent responses.
Severity: HIGH

ROOT CAUSE:
-----------
Mouse event interception by VerticalScroll container prevents text selection.

The messages use Static widgets which have allow_select=True, but the
VerticalScroll parent container consumes mouse events for scrolling,
preventing the Static widget from receiving text selection events.

TECHNICAL DETAILS:
------------------
Current Implementation:
  - Message widgets: inherit from ChatMessage(Static)
  - Container: VerticalScroll (#messages-container)
  - Widget types:
    • UserMessage (Static)
    • AssistantMessage (Static)
    • SystemMessage (Static)
    • LoadingIndicator (Static)
    • ErrorMessage (Static)

File Locations:
  - Message widgets: src/logai/ui/widgets/messages.py (lines 1-137)
  - Chat screen: src/logai/ui/screens/chat.py (lines 141-165, 229-325)
  - Styling: src/logai/ui/styles/app.tcss (lines 30-76)

-------------------

Static Widget:
  ✗ can_focus: False

  ✗ No text selection API
  ✗ No copy/clipboard support

  ✓ can_focus: True

  ✓ Copy support (Ctrl+C)

RichLog Widget:
  ✗ No text selection support

BEFORE/AFTER CODE:
-------------------

BEFORE (messages.py):
  from textual.widgets import Static

  class ChatMessage(Static):
      pass

  class UserMessage(ChatMessage):
      def __init__(self, content: str) -> None:
          super().__init__(f"[bold]You:[/bold] {content}")

AFTER (messages.py):
  from textual.widgets import TextArea

  class ChatMessage(TextArea):
      def __init__(self, content: str = "") -> None:
          super().__init__(text=content, read_only=True)

  class UserMessage(ChatMessage):
      def __init__(self, content: str) -> None:
          super().__init__(f"[bold]You:[/bold] {content}")
          self.add_class("user-message")

KEY INSIGHTS:
--------------
1. Static widget allows selection in theory (allow_select=True)
   but mouse events are intercepted by VerticalScroll container

2. TextArea handles text selection internally
   and is not affected by container event interception

3. read_only=True is the key
   - Disables editing completely
   - Keeps selection fully enabled
   - Zero visual differences

4. This is a standard solution
   - Used by many TUI applications
   - Textual documentation examples use this pattern
   - Battle-tested and reliable
