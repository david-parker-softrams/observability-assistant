SITUATION
=========
User reported that the "Add to Context" feature appears broken. When a user
clicks "Add to Context" with selected log entries, then asks the agent to
analyze them, the agent ignores the logs and asks to search for them instead.

Investigation Result: The feature is NOT broken. The bug is a missing system
prompt instruction.

KEY FINDING: 100% of the infrastructure works. The logs are successfully
delivered to the agent. The agent simply doesn't know what to do with them.

ROOT CAUSE (ONE SENTENCE)
=========================
The system prompt never tells the agent that user-provided logs might be in
context or that it should analyze them before using tools.

IMPACT
======
Users believe the feature is broken when it's actually 99% functional. This
undermines user confidence in the product.

THE FIX (HIGH LEVEL)
====================

What to do:
1. Add one section to the system prompt (src/logai/core/orchestrator.py)
2. Improve the message tone (src/logai/ui/screens/chat.py)

How long: 20 minutes
Risk: Minimal (just adding documentation)
Complexity: Low
Testing: Simple scenario-based test

DETAILED FINDINGS
=================

✓ WORKING (13/14 components):
  - UI captures log selections
  - Logs formatted as JSON
  - Logs stored in orchestrator memory
  - Logs retrieved on next message
  - Logs appended to message array
  - Logs sent to LLM provider
  - Message receives all three parts:
    1. System prompt (agent's instructions)
    2. User message (the question)
    3. Context logs (the data)

✗ BROKEN (1/14 components):
  - System prompt doesn't mention context logs
  - Agent doesn't know to check for them
  - Agent doesn't know to prioritize them

EVIDENCE
========

Logs ARE reaching the agent:
  - Stored at line 343 in orchestrator.py ✓
  - Retrieved at lines 435-478 in orchestrator.py ✓
  - Appended to messages at lines 1008-1009 in orchestrator.py ✓
  - Sent to LLM at lines 1030-1032 in orchestrator.py ✓

Agent IGNORES them because:
  - System prompt (lines 220-304) never mentions them ✗
  - System prompt teaches "fetch logs before analyzing"
  - Agent thinks it needs to fetch, not that they're provided

THE PARADOX
===========

Message array LLM receives:
[
  {"role": "system", "content": "You are an expert... Always fetch logs..."},
  {"role": "user", "content": "Analyze these logs"},
  {"role": "system", "content": "USER-SELECTED LOG ENTRIES: [entries...]"}
]

Agent's thought process:
  "User wants analysis. My instructions say 'fetch logs before analyzing'.
   I should fetch logs from CloudWatch first. Oh wait, I don't see any mention
   of logs being provided in context. Let me search for logs..."

What should happen:
  "I see user-provided logs in my context. My instructions should tell me
   these take priority. Let me analyze them."

THE FIX
=======

FIX 1 (CRITICAL - 5 minutes):
File: src/logai/core/orchestrator.py
Location: After line 300 (end of system prompt)

Add this section:

    ## User-Provided Log Entries

    Users can provide log entries directly via "Add to Context" feature.
    When you receive entries in your context:

    1. **RECOGNITION**: Look for "USER-SELECTED LOG ENTRIES for analysis"
    2. **PRIORITY**: ALWAYS analyze provided logs FIRST
    3. **ANALYSIS**: Provide insights based on provided logs
    4. **TOOLS**: Only use if context insufficient

    CRITICAL: Do NOT ignore provided logs and ask to search.

Result: Agent now knows what to do with context logs.

FIX 2 (HIGH - 5 minutes):
File: src/logai/ui/screens/chat.py
Location: Lines 431-442

Change message tone from:
  "Please analyze these logs and provide insights..."
To:
  "YOU MUST analyze these logs. Do NOT ask for a log group to search."

Result: Message is more commanding, reinforces system prompt.
